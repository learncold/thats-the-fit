# 서비스 요구사항

## 1. 서비스 목적

사용자가 원하는 의류 실측과 핏 키워드를 함께 지정하면, 쇼핑몰 상품 중 조건에 맞거나 실측이 유사한 상품의 사이즈를 찾아 비교할 수 있다.

사용자가 해결하려는 문제는 다음과 같다.

- 이미 잘 맞는 옷을 기준으로 다른 쇼핑몰에서 비슷한 핏의 옷을 찾기 어렵다.
- 상품명에 같은 핏 키워드가 있어도 실제 치수는 다를 수 있다.
- 쇼핑몰마다 실측 항목의 명칭, 단위, 측정 방식과 제공 범위가 다를 수 있다.

## 2. 현재 확정 내용

| 구분 | 내용 |
| --- | --- |
| 의류 종류 | 데님, 스웨터 등 종류별로 적절한 실측 항목을 사용한다. |
| 직접 입력 | 사용자가 비교할 실측 항목을 선택하고 보유한 옷의 실측값을 기준으로 입력해 검색한다. |
| 기존 상품 입력 | 상품명 또는 상품 URL로 서비스 DB에 등록된 상품을 찾고, 선택한 사이즈의 실측으로 비슷한 핏의 상품을 검색한다. |
| 최종 입력 데이터 | 총장·밑위·허리 너비 등 수치와 와이드·커브드 등 키워드를 결합한다. |
| 첫 출시 범위 | 데님 바지부터 구현한다. |
| 상품 데이터 | 선정한 쇼핑몰 2~3곳 |

## 3. 사용자 이용 흐름

### MVP 범위

1. 비교할 데님 실측 항목을 선택하고, 항목별 기준값과 허용 범위를 설정한 뒤 핏 키워드를 선택해 검색한다.
2. 상품명을 검색하거나 상품 URL을 붙여넣어 서비스 DB에 등록된 상품을 찾는다. 사이즈를 선택해 기준 실측을 채우고 유사 상품을 검색한다. 미등록 상품이면 실측 직접 입력을 안내한다.
3. 결과에서 기준 실측과 후보 실측의 차이, 핏 키워드, 가격·판매 상태를 확인한다.
4. 원본 쇼핑몰 상품 페이지로 이동할 수 있는 기능을 제공한다.

### 실측 조건 설정과 검색 결과 탐색

1. 사용자는 바지 도식에서 측정 위치를 확인하고 비교할 실측 항목을 선택해 조건 목록에 추가한다. 총장은 바지 옆 세로 방향, 허리단면은 허리선, 엉덩이단면과 허벅지단면은 각각 해당 높이, 밑위는 허리선에서 가랑이까지, 밑단단면은 한쪽 바지통의 밑단에 표시한다.
2. 추가한 항목별로 기준값을 cm 단위의 숫자로 입력하고 허용 범위를 조정한다. 등록 상품의 사이즈를 선택하면 확인된 실측 항목을 조건 목록에 추가하고 기준값을 채운다. 사용자는 핏 키워드를 선택해 각 태그를 선호 또는 필수로 지정할 수 있다.
3. 검색 결과가 표시되면 같은 화면에서 입력 폼을 접고 화면 한쪽에 검색 조건을 요약한다. 요약에는 검색에 적용한 실측값, 항목별 허용 범위, 선택한 핏 키워드와 필수·선호 상태를 표시한다. 결과 영역을 넓혀 상품과 사이즈별 실측 차이를 탐색할 수 있게 한다.
4. 요약에서 `조건 수정`을 누르면 선택한 실측 항목, 기준값, 허용 범위, 키워드 선택과 필수·선호 상태를 유지한 채 입력 폼을 다시 펼친다. 사용자는 조건을 수정하고 다시 검색할 수 있다.

### 후속 범위 제안

- 다른 의류 종류 확장 및 그에 따른 재질 비교 기능
- 계정, 개인 옷장 영구 저장, 찜, 검색 기록
- 기존 구매자 리뷰들 중 핏 관련된 부분 인용
- 서비스 DB에 없는 상품의 URL을 입력받아 실측 즉시 수집

## 4. 대표 사용자 시나리오

### US-01. 보유한 바지와 비슷한 상품 찾기

사용자는 허리단면, 총장 등 비교할 실측 항목을 선택한다. 잘 맞는 바지의 실측을 각 항목의 기준값으로 입력하고 허용 범위와 핏 키워드를 지정해 검색한다. 결과에서 실측 차이를 확인하고 쇼핑몰로 이동한다.

### US-02. 인터넷 상품을 기준으로 찾기

사용자는 상품명을 검색하거나 상품 URL을 붙여넣어 서비스에 등록된 상품을 찾고 해당 상품의 특정 사이즈를 선택한다. 확인된 실측 항목과 기준값이 조건 목록에 채워지면, 비교할 항목과 기준값, 허용 범위를 조정해 검색한다. 결과에서 실측 차이를 확인하고 쇼핑몰로 이동한다. 상품이 등록돼 있지 않으면 실측 직접 입력을 안내한다.

### US-03. 수집 데이터 검수

관리자는 검수가 필요한 실측 행을 열어 수집 API가 반환한 항목명과 값을 확인한다. 필요한 경우 판매자 실측표를 참고하고, 비교할 수 있는 값으로 확인되면 직접 입력해 저장한다.

## 5. 기능 요구사항

| ID | 요구사항 | 완료 기준 |
| --- | --- | --- |
| FR-01 | 의류 종류별로 선택할 수 있는 실측 항목을 제공한다. | MVP에서는 바지 도식에 6.1의 데님 실측 6개 항목과 측정 위치를 표시한다. 사용자가 항목을 선택하면 조건 목록에 추가한다. |
| FR-02 | 사용자가 선택한 항목의 기준 실측을 직접 입력한다. | 실측 항목을 하나 이상 선택하고, 선택한 모든 항목의 기준값을 cm 단위로 입력해야 검색할 수 있다. 양의 정수와 소수를 지원하고 미입력과 0을 구분한다. 선택한 항목이 없거나 기준값이 모두 비어 있으면 최소 하나의 실측을 입력하라고 안내한다. 일부만 비어 있으면 선택한 항목의 기준값을 모두 입력하라고 안내하고 검색을 실행하지 않는다. 0 이하·숫자가 아닌 값·범위 역전은 오류로 안내한다. |
| FR-03 | 기존 상품의 정보를 기준 실측으로 사용한다. | 상품명과 상품 URL 조회는 서비스 DB에 등록된 상품을 대상으로 한다. 두 방식 모두 상품을 찾으면 사이즈를 선택할 수 있다. 선택한 사이즈에서 확인된 실측 항목을 조건 목록에 추가하고 기준값을 채운다. 사용자는 채워진 기준값을 수정하고 유사 상품 검색을 실행할 수 있다. |
| FR-04 | 기준값과 검색 허용 범위를 지정한다. | 항목의 기준값이 처음 채워지면 6.1의 기본 허용 범위로 최솟값·최댓값을 채운다. 사용자는 기준값과 범위를 수정할 수 있다. 최솟값과 최댓값은 각각 조정할 수 있으며 두 경곗값을 모두 범위에 포함한다. |
| FR-05 | 실측과 핏 키워드를 결합한다. | 6.3의 키워드를 선택하지 않거나 여러 개 선택할 수 있다. 키워드를 새로 선택하면 기본값은 선호이며 필수로 바꿀 수 있다. 필수 키워드는 모두 일치해야 하고, 선호 키워드는 정렬에만 반영한다. |
| FR-06 | 후보를 조회한다. | 결과에 상품명과 사이즈가 함께 표시된다. 같은 상품의 다른 사이즈는 서로 다른 후보로 취급한다. |
| FR-07 | 후보를 정렬하여 표시한다. | 입력한 모든 실측 항목에 대해 비교 가능한 값이 있고 각 허용 범위를 충족하는 사이즈·옵션만 포함한다. 입력하지 않은 항목의 누락은 제외 사유가 아니다. 필수 키워드를 위반한 후보는 제외한다. 조건을 충족한 후보는 6.4에 따라 정렬한다. 같은 데이터와 조건에서는 동률 후보도 동일한 순서로 반환한다. |
| FR-08 | 검색 결과를 설명한다. | 비교에 사용한 항목과 기준·후보의 항목별 차이를 표시한다. 실측과 차이의 표시 단위는 cm다. 일치한 핏 키워드와 비교에 사용하지 못한 항목을 표시한다. |
| FR-09 | 상품 기본 정보를 제공한다. | 상품명, 쇼핑몰, 사이즈, 확인 가능한 가격·판매 상태, 원본 링크, 마지막 확인 시각을 표시한다. |
| FR-10 | 결과가 없는 경우 조건 수정을 돕는다. | 결과 없음과 시스템 오류를 구분한다. 조건 완화를 제안할 수 있지만 사용자 동의 없이 필수 조건을 변경하지 않는다. |
| FR-11 | 상품 데이터의 수집·입력·갱신을 지원한다. | 데이터 출처와 처리 결과를 기록한다. 수집 요청 실패와 정상 응답에서 실측을 확보하지 못한 경우를 구분한다. 같은 상품 사이즈를 반복 처리해도 중복 후보가 생기지 않는다. |
| FR-12 | 관리자가 수집 오류를 확인하고 검수가 필요한 실측을 수정한다. | 실패 원인과 원본을 확인하고 재처리할 수 있다. 수집 실측이 [검수 기준](mvp-design.md#2-수집-실측의-비교-기준과-검수)에 해당하면 관리자에게 알리고 검수 목록에 추가한다. 관리자는 상품·사이즈·옵션별로 수집 API가 반환한 실측 항목명과 값을 확인하고, 비교할 값을 직접 입력해 저장할 수 있다. 저장한 값이 검색에 반영된다. |
| FR-13 | 기준 상품을 사용할 수 없는 경우를 안내한다. | 상품명 검색에 결과가 없거나 URL의 상품이 미등록 상태이면 실측 직접 입력을 안내한다. 지원하지 않는 URL과 선택한 사이즈의 실측 부족도 각각 원인을 표시하고 실측 직접 입력을 안내한다. |
| FR-14 | 같은 화면에서 실측 조건 설정과 검색 결과 탐색을 오간다. | 실측 항목을 선택해 조건에 추가한 뒤 기준값과 허용 범위를 설정하고 핏 태그를 선택할 수 있다. 검색 결과가 표시되면 입력 폼을 조건 요약으로 접고 결과 영역을 넓힌다. `조건 수정`을 누르면 선택 항목과 적용한 조건이 채워진 폼을 다시 펼친다. |

## 6. 실측과 검색 기준

### 6.1 데님 항목

데님 실측의 사용자 입력과 화면 표시 단위는 모두 cm다. 수집값은 출처에서 단위와 측정 기준을 확인한 뒤 비교에 사용한다.

허리단면을 직접 입력할 때는 입력란 근처에 ‘허리둘레 대신, 바지를 평평하게 놓고 잰 허리 너비를 입력하세요.’라고 안내한다. 입력값은 허리단면(cm)으로 그대로 사용하며, 값의 크기에 따라 둘레로 추정하거나 자동 환산하지 않는다.

| 항목 | 입력·표시 단위 | 기본 허용 범위 |
| --- | --- | --- |
| 총장 | cm | 기준값 ±2 cm |
| 허리단면 | cm | 기준값 ±1 cm |
| 엉덩이단면 | cm | 기준값 ±1 cm |
| 허벅지단면 | cm | 기준값 ±1 cm |
| 밑위 | cm | 기준값 ±1 cm |
| 밑단단면 | cm | 기준값 ±1 cm |

### 6.2 공통 규칙

- 같은 상품의 사이즈·옵션을 별도 후보로 비교한다.
- 관리자는 검수가 필요한 실측 행의 수집 출처와 API 응답을 확인할 수 있어야 한다.
- 누락되거나 측정 기준을 확인할 수 없는 값, 관리자 검수가 필요한 값은 해당 실측 조건을 충족한 것으로 처리하지 않는다.
- 소재·신축성은 제공되는 경우 비교 보조 정보로 표시한다.
- 가격·판매 상태·실측은 마지막 확인 시각을 추적할 수 있어야 한다.

실측을 비교용으로 변환하는 방법과 검수 절차는 [수집 실측 설계](mvp-design.md#2-수집-실측의-비교-기준과-검수)를 따른다.

### 6.3 핏 키워드 규칙

- MVP에서는 와이드, 스트레이트(일자), 부츠컷, 슬림, 테이퍼드, 커브드 6개를 제공한다.
- 판매자 원문에서 확인된 핏만 태그로 적용한다. 매핑을 보류한 표현은 원문을 보존하며 검색 조건의 일치나 선호 정렬에 반영하지 않는다. 상세 기준은 [핏 키워드 매핑 설계](mvp-design.md#3-핏-키워드-매핑)를 따른다.

- 입력한 실측의 허용 범위를 모두 만족하는 후보 중 필수 키워드가 모두 확인된 후보를 남긴다. 필수 키워드가 하나라도 없거나 확인되지 않으면 제외한다.
- 선호 키워드의 일치 여부는 6.4에 따라 실측 점수가 같은 후보의 순서에 반영한다. 선호 키워드가 일치하지 않거나 확인되지 않아도 필수 조건을 충족하면 결과에 포함한다.

### 6.4 검색 결과 정렬 규칙

- 기준 실측에 더 가까운 후보를 먼저 표시한다.
- 실측 유사도가 같으면 일치한 선호 키워드가 많은 후보를 먼저 표시한다. 여기까지 같으면 동일한 조건과 데이터에서 결과 순서를 일관되게 유지한다.

실측 점수 계산과 동률 처리 순서는 [검색 결과 정렬 설계](mvp-design.md#4-검색-결과-정렬)를 따른다.

| NFR-01 | 응답 성능 | 상품 사이즈 1만 건, 동시 사용자 10명 조건에서 검색 API p95 1초 이내를 초기 목표로 검토한다. 하드웨어·검색 조건·워밍업·캐시 상태·측정 시간을 함께 기록한다. 수치는 범위 확정 시 재검토한다. |
| NFR-02 | 입력·검색 정확성 | 단위 변환, 허용 범위 경계, 비대칭 범위, 결측값, 복수 키워드, 동률 정렬에 대해 기대 결과를 검증한다. |
| NFR-03 | 갱신 안정성 | 같은 데이터를 재처리해도 중복되지 않고, 수집 실패 시 마지막 정상 데이터와 확인 시각을 유지한다. |
| NFR-04 | 접근 제어 | 데이터 수정·검수 등 운영 기능은 일반 검색 이용자가 실행할 수 없다. 상품 URL은 지원하는 쇼핑몰의 상품 주소 형식만 인식하고, 조회는 서비스 DB에서만 수행한다. |
| NFR-05 | 관측 가능성 | 검색 지연·오류와 수집 성공·실패를 확인할 수 있고, 장애가 난 요청 또는 작업을 추적할 수 있다. |
| NFR-06 | 배포 재현성 | 저장소의 문서와 설정으로 빌드·테스트·실행·배포 절차를 재현할 수 있다. 비밀값은 저장소에 포함하지 않는다. |
| NFR-07 | 사용성 | 모바일과 데스크톱에서 실측 입력·검색·차이 확인·쇼핑몰 이동이 가능하다. |

## 8. MVP 인수 시나리오

| ID | 상황 | 기대 결과 |
| --- | --- | --- |
| AC-01 | 허리 단면 40cm, 총장 104cm를 입력하고 허리 40~42cm, 총장 102~106cm를 필수 범위로 지정한다. | 반환된 모든 후보는 두 범위를 경계값 포함 만족한다. |
| AC-02 | 와이드·커브드를 모두 필수 키워드로 지정한다. | 두 속성이 확인된 후보만 반환한다. |
| AC-03 | 허리단면과 총장을 입력한다. 같은 상품의 M 사이즈는 총장이 누락되거나 비교할 수 없고, L 사이즈는 두 항목 모두 범위 안이다. | M 사이즈만 제외하고 L 사이즈는 결과에 포함한다. |
| AC-04 | 기준 상품의 입력으로 특정 상품의 M 사이즈를 입력한다. | 확인된 실측 항목이 조건 목록에 추가되고 기준값이 채워진다. |
| AC-05 | 수집 API가 30 사이즈의 `허리단면`을 80으로 반환하고 이 값이 검수 기준을 벗어난다. 관리자가 API 응답을 확인하고 판매자 실측표를 참고해 허리단면 40 cm를 입력한 뒤 저장한다. | 관리자에게 알림이 표시되고 검수 목록에서 API의 항목명과 값 80을 확인할 수 있다. 검수 대상 값은 검색에 쓰이지 않으며, 저장 후에는 40 cm가 해당 사이즈의 검색용 허리단면으로 사용된다. |
| AC-06 | 동일한 상품 사이즈를 두 번 수집한다. | 하나의 후보가 갱신되고 중복 결과가 생기지 않는다. |
| AC-07 | 상품 갱신 요청이 시간 초과된다. | 마지막 정상 데이터가 유지되며, 최신 갱신 실패를 추적할 수 있다. |
| AC-08 | 모든 필수 조건을 만족하는 상품이 없다. | 결과 없음을 표시하고 조건 수정 수단을 제공한다. 조건을 임의로 완화하지 않는다. |
| AC-09 | 비교 결과에서 후보의 총장이 기준보다 1cm 짧다. | 총장 차이 -1cm를 함께 표시한다. |
| AC-10 | 허리단면과 총장을 추가한 뒤 허리단면 기준값 40.5 cm만 입력해 검색한다. | 추가한 기준은 모두 수치값을 입력해야 한다고 안내하고, 검색은 불가능하다. |
| AC-11 | 실측 항목을 선택하지 않았거나, 추가한 항목의 기준값을 모두 비운 채 검색한다. | 검색을 실행하지 않고 실측을 최소 1개 입력하라고 안내한다. |
| AC-12 | 바지 도식에서 허리단면과 총장을 선택해 추가하고, 기준값으로 각각 40 cm와 104 cm를 입력한다. | 선택한 두 항목이 조건 목록에 추가된다. 최초 기본 범위는 허리단면 39~41 cm, 총장 102~106 cm이며 두 범위의 최솟값·최댓값을 각각 수정할 수 있다. |
| AC-13 | 와이드를 필수로 지정하고 커브드를 선호로 선택한다. | 새로 선택한 커브드는 선호로 설정된다. 두 후보가 모두 결과에 포함되며, 커브드 일치는 정렬에 반영된다. |
| AC-14 | 허리단면 40 cm, 총장 104 cm, 커브드 선호로 검색한다. 후보 A는 허리단면 40.5 cm·총장 104 cm이며 커브드가 미확인이다. 후보 B는 40 cm·105 cm, 후보 C는 40.5 cm·105 cm이며 B와 C는 커브드가 확인된다. | 실측 유사도가 같은 A와 B 중 선호 키워드가 일치한 B를 먼저 표시한다. 결과는 B → A → C 순이다. |
| AC-15 | 실측 점수와 선호 키워드 일치 개수가 같은 후보를 동일한 조건과 데이터로 두 번 검색한다. | 두 검색의 결과 순서가 같다. |
| AC-16 | 결과 화면의 조건 요약에서 `조건 수정`을 누른 뒤 허용 범위를 바꾸고 다시 검색한다. | 선택한 실측 항목과 기존 기준값, 허용 범위, 선택 태그와 필수·선호 상태를 유지한 채 폼이 펼쳐진다. 다시 검색하면 수정한 허용 범위가 결과에 반영된다. |

## 10. 기술 선정과 후속 문서

데이터와 검색의 상세 규칙은 [MVP 설계](mvp-design.md), 기술 선택은 [기술 스택](../stack.md)에 기록한다.

진행 순서는 다음과 같이 제안한다.

1. 이 문서의 제안과 미정 사항을 검토해 MVP 범위를 확정한다.
2. 실측 입력 → 검색 결과 → 상품 비교의 화면 흐름을 정한다.
3. 데이터 모델·ERD와 검색 조건·순위 정책을 구체화한다.
4. API 명세, 기술 결정, 개발 작업 목록을 작성한다.
5. 사용자 흐름 하나를 입력부터 배포까지 연결해 구현하고 인수 시나리오로 확인한다.
