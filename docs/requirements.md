# 서비스 요구사항

- 문서 상태: v0.1
- 최종 수정일: 2026-11-09

## 1. 서비스 목적

사용자가 원하는 의류 실측과 핏 키워드를 함께 지정하면, 쇼핑몰 상품 중 조건에 맞거나 실측이 유사한 상품의 사이즈를 찾아 비교할 수 있다.

사용자가 해결하려는 문제는 다음과 같다.

- 이미 잘 맞는 옷을 기준으로 다른 쇼핑몰에서 비슷한 핏의 옷을 찾기 어렵다.
- 상품명에 같은 핏 키워드가 있어도 실제 치수는 다를 수 있다.
- 쇼핑몰마다 실측 항목의 명칭, 단위, 측정 방식과 제공 범위가 다를 수 있다.

## 2. 현재 확정 내용

| 구분 | 내용 |
| --- | --- |
| 의류 종류 | 데님, 스웨터 등 종류별로 적절한 실측 항목을 사용한다. |
| 직접 입력 | 사용자가 보유한 옷의 실측을 입력해 검색한다. |
| 기존 상품 입력 | 인터넷 의류 상품을 선택해 비슷한 핏의 상품을 검색한다. |
| 최종 입력 데이터 | 총장·밑위·허리 너비 등 수치와 와이드·커브드 등 키워드를 결합한다. |
| 백엔드 | Spring Boot를 중심으로 개발한다. |
| 첫 출시 범위 | 데님 바지부터 구현한다. |
| 상품 데이터 | 선정한 쇼핑몰 2~3곳 |

## 3. 사용자 이용 흐름

### MVP 범위

1. 데님 바지 실측을 직접 입력하고 핏 키워드를 선택해 검색한다.
2. 서비스에 등록된 인터넷 상품과 그 사이즈를 선택해 유사 상품을 검색한다.
3. 결과에서 기준 실측과 후보 실측의 차이, 핏 키워드, 가격·판매 상태를 확인한다.
4. 원본 쇼핑몰 상품 페이지로 이동할 수 있는 기능을 제공한다.

### 후속 범위 제안

- 다른 의류 종류 확장 및 그에 따른 재질 비교 기능
- 계정, 개인 옷장 영구 저장, 찜, 검색 기록
- 기존 구매자 리뷰들 중 핏 관련된 부분 인용

## 4. 대표 사용자 시나리오

### US-01. 보유한 바지와 비슷한 상품 찾기

사용자는 잘 맞는 바지의 허리 단면, 총장 등 실측을 입력한다. 항목별 허용 범위와 핏 키워드를 지정하고 검색한다. 결과에서 실측 차이를 확인하고 쇼핑몰로 이동한다.

### US-02. 인터넷 상품을 기준으로 찾기

사용자는 서비스에 등록된 상품을 찾고 해당 상품의 특정 사이즈를 선택한다. 제공된 실측으로 검색 조건을 채운 뒤, 원하는 항목과 허용 범위를 수정해 검색한다. 결과에서 실측 차이를 확인하고 쇼핑몰로 이동한다.

### US-03. 수집 데이터 검수

운영자는 수집 데이터를 검토한다. 원본과 추출 값을 비교해 수정 또는 게시 제외를 결정한다.

## 5. 기능 요구사항

| ID | 요구사항 | 완료 기준 |
| --- | --- | --- |
| FR-01 | 의류 종류별로 실측 입력 항목을 제공한다. | MVP에서는 데님 항목이 표시되고, 각 항목에 명칭·단위·측정 안내가 함께 나온다. |
| FR-02 | 사용자가 기준 실측을 직접 입력한다. | 소수 입력을 지원한다. 미입력과 0을 구분하며, 0 이하·숫자가 아닌 값·범위 역전은 오류로 안내한다. |
| FR-03 | 기존 상품의 정보를 기준 실측으로 사용한다. | 선택한 사이즈의 알려진 실측만 채워지며, 누락값을 임의로 채우지 않는다. 상품 선택만으로 검색이 실행되지 않고 입력값을 수정후 검색할 수 있도록 한다. |
| FR-04 | 기준값과 검색 허용 범위를 지정한다. | 항목별 최솟값·최댓값을 수정할 수 있다. '기준보다 작지 않게'처럼 비대칭 범위를 표현할 수 있다. |
| FR-05 | 실측과 핏 키워드를 결합한다. | 키워드를 복수 선택하고 각각 필수 조건 또는 선호 조건으로 구분한다. 필수 키워드는 모두 만족하는 후보를 검색한다. |
| FR-06 | 후보를 조회한다. | 결과에 상품명과 사이즈가 함께 표시된다. 같은 상품의 다른 사이즈는 서로 다른 후보로 취급한다. |
| FR-07 | 후보를 정렬하여 표시한다. | 필수 범위와 필수 키워드를 위반한 후보는 제외한다. 같은 데이터·조건·알고리즘 버전은 동률 처리까지 동일한 순서를 반환한다. |
| FR-08 | 검색 결과를 설명한다. | 기준과 후보의 항목별 차이를 cm로 표시한다. 일치한 핏 키워드와 비교에 사용하지 못한 항목을 표시한다. |
| FR-09 | 상품 기본 정보를 제공한다. | 상품명, 쇼핑몰, 사이즈, 확인 가능한 가격·판매 상태, 원본 링크, 마지막 확인 시각을 표시한다. |
| FR-10 | 결과가 없는 경우 조건 수정을 돕는다. | 결과 없음과 시스템 오류를 구분한다. 조건 완화를 제안할 수 있지만 사용자 동의 없이 필수 조건을 변경하지 않는다. |
| FR-11 | 상품 데이터의 수집·입력·갱신을 지원한다. | 데이터 출처와 처리 결과를 기록한다. 같은 상품 사이즈를 반복 처리해도 중복 후보가 생기지 않는다. |
| FR-12 | 수집 오류를 검수한다. | 실패 원인과 원본을 확인하고 재처리할 수 있다. |
| FR-13 | 지원하지 않는 기준 상품을 안내한다. | 미등록 상품·지원하지 않는 URL·선택 사이즈의 실측 부족은 원인과 직접 입력 대안을 안내한다. |

## 6. 실측 데이터 모델링

### 6.1 데님 항목

| 항목 | 내부 비교 기준 제안 | 주의사항 |
| --- | --- | --- |
| 총장 | cm | 측정 위치·방식이 다를 수 있음 |
| 허리 | 단면 cm | 둘레 값은 출처에서 둘레임을 확인한 경우에만 변환 |
| 엉덩이 | 단면 cm | 측정 위치 정보를 함께 보관 |
| 허벅지 | 단면 cm | 가랑이 기준 측정 위치가 다를 수 있음 |
| 앞밑위 | cm | 뒷밑위와 구분 |
| 밑단 | 단면 cm | 한쪽 바지통 기준인지 확인 |

### 6.2 공통 규칙

- 상품과 판매 사이즈를 분리한다. 실측이 다르면 별도 후보로 구분한다.
- 원문 항목명·값·단위·측정 기준과 정규화 결과·변환 근거를 함께 보관한다.
- 측정 방식이 불명확하거나 서로 비교하기 어려운 값은 자동으로 동등하게 취급하지 않는다.
- 실측 누락은 0으로 저장하거나 평균값으로 보완하지 않는다.
- 키워드는 복수 속성으로 관리한다. (예: 와이드와 커브드 동시 입력)
- 소재·신축성은 제공되는 경우 비교 보조 정보로 표시한다.
- 가격·판매 상태·실측은 마지막 확인 시각을 추적할 수 있어야 한다.

| NFR-03 | 갱신 안정성 | 같은 데이터를 재처리해도 중복되지 않고, 수집 실패 시 마지막 정상 데이터와 확인 시각을 유지한다. |
| NFR-04 | 접근 제어 | 데이터 수정·검수 등 운영 기능은 일반 검색 이용자가 실행할 수 없다. 외부 URL 입력을 지원하면 허용된 쇼핑몰과 요청 대상을 제한한다. |
| NFR-05 | 관측 가능성 | 검색 지연·오류와 수집 성공·실패를 확인할 수 있고, 장애가 난 요청 또는 작업을 추적할 수 있다. |
| NFR-06 | 배포 재현성 | 저장소의 문서와 설정으로 빌드·테스트·실행·배포 절차를 재현할 수 있다. 비밀값은 저장소에 포함하지 않는다. |
| NFR-07 | 사용성 | 모바일과 데스크톱에서 실측 입력·검색·차이 확인·쇼핑몰 이동이 가능하다. |

## 8. MVP 인수 시나리오

| ID | 상황 | 기대 결과 |
| --- | --- | --- |
| AC-01 | 허리 단면 40cm, 총장 104cm를 입력하고 허리 40~42cm, 총장 102~106cm를 필수 범위로 지정한다. | 반환된 모든 후보는 두 범위를 경계값 포함 만족한다. |
| AC-02 | 와이드·커브드를 모두 필수 키워드로 지정한다. | 두 속성이 확인된 후보만 반환한다. |
| AC-03 | 허리가 필수 조건인데 후보 상품의 허리 실측이 없다. | 해당 후보는 결과에서 제외된다. |
| AC-04 | 기준 상품의 M 사이즈를 선택한다. | M의 실측이 채워지고 누락 항목이 표시된다. 다른 사이즈의 값이 섞이지 않는다. |
| AC-05 | 허리 둘레 80cm로 명확하게 표시된 원본 데이터를 입력한다. | 단면 40cm로 비교하되 원문과 변환 근거를 확인할 수 있다. |
| AC-06 | 동일한 상품 사이즈를 두 번 수집한다. | 하나의 후보가 갱신되고 중복 결과가 생기지 않는다. |
| AC-07 | 상품 갱신 요청이 시간 초과된다. | 마지막 정상 데이터가 유지되며, 최신 갱신 실패를 추적할 수 있다. |
| AC-08 | 모든 필수 조건을 만족하는 상품이 없다. | 결과 없음을 표시하고 조건 수정 수단을 제공한다. 조건을 임의로 완화하지 않는다. |
| AC-09 | 비교 결과에서 후보의 총장이 기준보다 1cm 짧다. | 총장 차이 -1cm를 표시하고 원본 상품으로 이동할 수 있다. |

## 10. 기술 선정과 후속 문서

이 문서는 요구사항을 다룬다. Maven·Gradle, MySQL·PostgreSQL, 검색 엔진·캐시 도입 여부는 요구사항 확정 후 기술 결정 문서에서 근거와 함께 선택한다.

진행 순서는 다음과 같이 제안한다.

1. 이 문서의 제안과 미정 사항을 검토해 MVP 범위를 확정한다.
2. 실측 입력 → 검색 결과 → 상품 비교의 화면 흐름을 정한다.
3. 데이터 모델·ERD와 검색 조건·순위 정책을 구체화한다.
4. API 명세, 기술 결정, 개발 작업 목록을 작성한다.
5. 사용자 흐름 하나를 입력부터 배포까지 연결해 구현하고 인수 시나리오로 확인한다.
