# MVP 데이터·검색 설계

- 관련 문서: [서비스 요구사항](requirements.md), [상품·옵션 식별 DBML 초안](product-identity.dbml), [수집 안내](scraping_guide.md)

## 1. 상품·사이즈 식별

지원하는 상품 URL에서 쇼핑몰과 원본 상품 ID를 식별해 등록 상품을 찾는다. 상품과 사이즈·옵션의 내부 ID 및 유일성 규칙은 [DBML 초안](product-identity.dbml)에 기록한다.

지그재그 상품 `172494364`의 수집 응답에서 S 사이즈의 `총장(미들)`은 100.3 cm, `총장(롱)`은 105.4 cm였다. 같은 상품과 사이즈명이라도 `option_values`의 기장값이 달라 서로 다른 사이즈·옵션으로 식별한다. [검증 상품](https://zigzag.kr/catalog/products/172494364)

## 2. 수집 실측의 비교 기준과 검수

입력 단위와 기본 허용 범위는 [요구사항 6.1](requirements.md#61-데님-항목)을 따른다.
검색용 실측과 검수 대기 행은 MVP 실측 6개를 정의한 [DBML의 `measurement_type` enum](product-identity.dbml)을 공유한다.

| 항목 | 측정·비교 시 주의사항 |
| --- | --- |
| 총장 | 측정 위치·방식이 다를 수 있음 |
| 허리단면 | 둘레로 확인된 수집값은 관리자가 비교에 사용할 단면값으로 직접 입력 |
| 엉덩이단면 | 측정 위치 정보를 함께 보관 |
| 허벅지단면 | 가랑이 기준 측정 위치가 다를 수 있음 |
| 밑위 | 출처에서 앞밑위와 뒷밑위가 확인되면 구분하고, 서로 다른 기준은 함께 비교하지 않음 |
| 밑단단면 | 한쪽 바지통 기준인지 확인 |

수집 실측이 아래 사유에 해당하면 `pending_measurement_reviews`에 등록한다. `reason_code`는 [DBML의 `measurement_review_reason` enum](product-identity.dbml)으로 제한한다.

| 검수 사유 | 등록 기준 |
| --- | --- |
| `out_of_range` | 수집된 숫자가 해당 실측 항목의 검수 범위를 벗어난 경우. 항목별 범위는 수집 표본을 바탕으로 정한다. |
| `ambiguous_value` | 사이즈·옵션과 실측 항목은 확인됐지만, 복합 문자열 등에서 비교할 단일 치수를 확정하기 어려워 원본 확인이 필요한 경우. |
| `conflicting_values` | 서로 다른 수집 출처가 같은 사이즈·옵션의 같은 실측 항목에 대해 서로 다른 값을 제공한 경우. |

- 대기 행은 연결이 확인된 사이즈·옵션 ID와 실측 항목(`measurement_type`)의 조합당 하나를 둔다. 같은 항목이 다시 수집되면 기존 대기 행에 응답 내용과 수집 시각을 갱신한다. 연결할 사이즈·옵션이 불명확하면 추측해 연결하지 않는다.
- `source_snapshot`에는 문제가 된 사이즈 행, 항목명과 값, 해석에 필요한 열 제목·단위·측정 안내 중 응답에 있는 정보만 저장한다. 출처 API, 수집 시각, 검수 사유도 함께 기록한다. 관리자 화면은 저장된 응답을 표시한다. 토큰·쿠키·개인 식별값·서명 URL은 저장 대상에서 제외한다.
- 검색은 검수 대기 행이 있는 사이즈·옵션의 해당 실측 항목을 비교에서 제외한다. 관리자는 저장된 응답을 확인하고, 필요하면 판매자 실측표나 측정 안내를 참고한다.
- 관리자가 수정값을 저장하면 `variant_measurements`의 해당 항목을 추가 또는 갱신하고 대기 행을 삭제한다. 두 작업은 한 트랜잭션에서 처리한다. 검수 결과 이력과 개별 변환 근거의 별도 보관은 MVP 범위에서 제외한다.
- 측정 방식이 불명확하거나 서로 비교하기 어려운 값은 자동으로 동등하게 취급하지 않는다.
- 실측 누락은 0으로 저장하거나 평균값으로 보완하지 않는다.
- 0, 단일 치수로 해석할 수 없는 복합값, 단위나 측정 기준이 불명확한 값은 검색 조건을 충족한 것으로 처리하지 않는다.

### 2.1 실측 수집 결과와 검색 반영

실측 수집에 실패하거나 정상 응답에서 실측을 확보하지 못하면 `measurement_collection_issues`에 상품 ID, 시도 종료 시각, 원인 코드를 기록한다. 재시도에도 같은 규칙을 적용한다.

| 원인 코드 | 판단 기준 |
| --- | --- |
| `request_timeout` | 요청 또는 실측 응답 대기가 제한 시간을 넘겼다. |
| `access_denied` | 세션 만료, 권한 오류 또는 접근 차단을 확인했다. |
| `request_failed` | 네트워크 오류나 서버 오류 등 그 밖의 요청 실패를 확인했다. |
| `invalid_response` | 응답을 받았으나 실측 응답 형식을 해석할 수 없다. |
| `no_measurements` | 정상 응답을 해석했으나 실측을 확보하지 못했다. |

- 요청 실패나 실측 미확보 시 기존 실측과 검수 대기 행, 마지막 실측 수신 시각을 유지한다.
- 실측을 수신하면 `products.last_measurements_received_at`을 갱신한다. 검수 대상만 수신한 경우도 포함하며, 한 번도 실측을 수신한 적이 없으면 시각을 비워 둔다. 검색에 사용할 수 있는 값은 `variant_measurements`에 추가 또는 갱신하고, 검수 대상은 `pending_measurement_reviews`에 등록한다.
- 일부 항목만 수집된 사이즈·옵션은 확인된 항목만 반영한다. 빠진 항목은 새 행을 만들지 않고 기존값과 검수 대기 행을 유지한다. 해당 사이즈·옵션에서 특정 항목이 더 이상 제공되지 않는다고 출처에서 확인하면 현재 실측과 대기 행을 제거해 검색에서 제외한다.
- 사용자가 선택한 모든 실측 항목에 비교 가능한 현재값이 있고 허용 범위를 충족해야 해당 사이즈·옵션이 검색 결과에 포함된다. 예를 들어 M 사이즈의 허리단면만 유효하고 총장은 저장된 값이 없으며 허벅지단면은 검수 대기라면, 허리단면만 선택한 검색에 포함될 수 있다. 총장이나 허벅지단면도 선택하면 M을 제외하고 L 등 다른 사이즈는 각자의 실측으로 판단한다.
- 마지막 실측 수신 시각이 없거나 최신 문제의 종료 시각이 마지막 수신 시각보다 늦으면, 최신 문제 코드로 재시도 여부를 판단한다. 타임아웃처럼 재시도로 해결할 수 있는 경우를 대상으로 삼고, `no_measurements`는 다음 정기 수집 때 다시 확인한다. 자동 재시도 횟수와 간격은 수집 작업의 정책으로 정한다.

### 2.2 관리자 페이지

관리자는 `/admin`에서 관리자 계정으로 로그인한 뒤 수집기를 실행하고, 수집 오류를 확인해 재처리하거나 검수 대기 중인 실측을 검수할 수 있다. 관리자 기능은 [요구사항 FR-12](requirements.md#5-기능-요구사항)를 따른다.

## 3. 핏 키워드 매핑

- 검색용 핏 태그는 `product_variants.fit_tags`에 `fit_tag` enum 배열로 저장한다. 확인된 태그가 없으면 빈 배열을 사용한다. DB는 배열의 전체 원소 수와 확인된 서로 다른 태그 수가 같은지 검사해 중복 태그와 `NULL` 원소를 막는다. enum에 태그를 추가할 때는 검사 제약의 태그 목록도 함께 갱신한다.
- 판매 옵션에서 핏을 고를 수 있으면 원본 옵션값을 `option_values`에 기록하고, 해당 사이즈·옵션의 `fit_tags`에 확인된 태그를 저장한다. 공통 핏이 확인되면 적용되는 사이즈·옵션에 각각 기록한다. 필수 키워드의 일치와 선호 키워드의 개수는 실측을 비교하는 같은 사이즈·옵션의 `fit_tags`를 기준으로 판단한다.
- 상품명과 판매자 상세 설명에서 해당 바지의 핏을 확인한다. 같은 바지에 명확한 핏이 여러 개 표시되면 각각 태그를 붙인다. 예를 들어 ‘와이드 커브드’는 와이드와 커브드로, ‘슬림 일자’는 슬림과 스트레이트로 기록한다. 묶음 상품은 각 바지에 해당하는 표현만 적용한다. 어느 구성품의 핏인지 확인할 수 없는 표현은 원문만 보존한다.
- 아래 표의 복합 표현은 단어별 규칙보다 먼저 적용한다. ‘세미와이드’와 ‘세미 와이드’처럼 띄어쓰기만 다른 표현은 같은 규칙을 적용한다. 원문만 보존하는 표현은 그 표현을 근거로 태그를 붙이지 않으며, 필수 조건의 일치나 선호 정렬에도 반영하지 않는다. 같은 바지에서 별도로 확인된 태그는 적용한다.

| 원문 표현 | MVP 매핑 |
| --- | --- |
| 일자, 일자핏, 세미 스트레이트 | 스트레이트 |
| 배럴, 배럴핏 | 바지의 핏을 뜻할 때 커브드 |
| 벌룬, 벌룬핏, 세미 벌룬 | 판매자가 커브드라고 명시하거나 다리의 곡선 실루엣을 명확히 설명하면 커브드. 그 외에는 원문만 보존한다. |
| 세미 부츠컷 | 부츠컷 |
| 플레어, 세미 플레어 | 원문만 보존한다. 같은 바지에 부츠컷 표기가 있으면 그 표기를 근거로 부츠컷을 붙인다. |
| 세미와이드 | 원문만 보존한다. 예를 들어 ‘세미와이드 일자’는 스트레이트, ‘세미 와이드 커브드’는 커브드로 기록한다. |
| 배기, 배기핏 | 원문만 보존한다. 밑단으로 갈수록 좁아진다는 설명만으로는 테이퍼드를 붙이지 않는다. 테이퍼드 표기가 있으면 그 표기를 근거로 붙인다. |
| 테이퍼드 일자 | 같은 바지의 핏을 설명하는 경우 테이퍼드만 붙이고 ‘일자’는 원문으로 보존한다. |

## 4. 검색 결과 정렬

1. **실측 점수가 작은 순**으로 정렬한다. 기준값이 있는 항목마다 후보값과 기준값의 차이의 절댓값을 6.1의 기본 허용 오차로 나누고, 그 값들의 평균을 실측 점수로 사용한다. 총장은 2 cm, 나머지 항목은 1 cm로 나눈다. 사용자가 수정한 허용 범위는 후보 포함 여부를 판단할 때 사용한다.
2. 실측 점수가 같으면 **일치한 선호 키워드가 많은 순**으로 정렬한다. 선택한 선호 키워드가 없으면 이 기준을 건너뛴다.
3. 앞 기준이 모두 같으면 **쇼핑몰 식별자 → 상품 ID → 사이즈·옵션 식별자** 순으로 각각 오름차순 정렬한다.

요구사항 AC-14 예시에서 실측 점수는 A와 B가 0.25이고 C가 0.50이다. 선호 키워드까지 적용한 순서는 B → A → C다.
